# Tidy website

A web app for household tasks, quick requests, assignments, routines, family planning, calendar import and grocery preparation. The deployable site is in `web/`. Only the fourteen reviewed runtime files are published; tests, screenshots and any saved user data are excluded.

## This change

The first visit offers calendar setup or **Not now**. **Sections → Calendar** offers Google and Outlook account connections plus file import. Neither provider has a registered application ID in this deployment yet, so the account buttons explain **setup required** before loading any provider SDK or claiming access. The website cannot request permission to read the phone's Calendar database; iCloud/device-only calendars still need file import or an installed app. No Tidy account sync or cross-device private storage is configured.

Once registered, Google Identity Services and Microsoft's official MSAL request read-only calendar access in the provider's popup. Tidy reads accessible calendars and their expanded events for the next 60 days, with bounded pagination and all-or-nothing validation. Free/transparent events do not block planning; Google busy-only shared calendars are explicitly outside the readable snapshot. Tokens remain in memory, outside local storage and backups; the official MSAL SDK may use session storage for temporary PKCE/interaction metadata. Refresh is explicit and expired access requires Connect again. Disconnect clears this tab's session, does not revoke the provider's grant, and leaves the saved snapshot available. Planning uses one account source or file snapshot at a time; replacing a different source requires confirmation.

Importing a fresh `.ics` file refreshes the local snapshot; an invalid or unsupported file leaves the previous calendar intact. After reloading, account snapshots remain as saved data but authorization must be renewed before refreshing. Tested SDK/API fixtures demonstrate application handling, not successful real account consent or iPhone popup behavior. Real registration, consent, popup behavior and provider responses remain to be verified.

**My usual hours** confirms separate workdays and school days, work hours, children returning home, planning limits, task lengths and buffers. Starting values are editable examples and automatic planning remains off until enabled. After confirmation, a request such as “I have to do work with the kids” gets an actual task time after applicable work/school hours, avoiding imported commitments and existing timed responsibilities. Tidy saves its duration, explanation and browser reminder, then opens **My day plan**. Without confirmed hours, it saves an untimed task and offers setup. **Organise my day** fits flexible tasks into the selected day, leaves fixed dates and appointments in place, and reports tasks that cannot fit. It does not contact providers or write to an external calendar.

Calendar imports cover a bounded 60-day window and up to 1,000 occurrences, including overlapping events. Supported recurrence is daily/weekly with bounded intervals, counts, end dates and exclusions. Unknown time zones, ambiguous daylight-saving times, monthly/advanced recurrence and recurrence overrides reject the whole import rather than silently dropping busy time. Local floating times use Dubai time with an explicit import note. Planning checks each proposed slot against the exact imported coverage window; stale snapshots need re-importing. Calendar export downloads the next seven days of actual timed tasks and repeating occurrences for manual review/import; it does not create calendar alarms or an ongoing recurring series.

Calendar data, confirmed hours and optional task duration/explanations are included in Tidy backups. Older backups retain their original shape until the new features are saved. The responsive website works at phone, tablet and desktop widths; importing on one device does not sync private data to another device. Native phone-calendar permissions, provider registration and secure cloud storage remain separate integration work.

Tidy now has five main buttons: **Today**, **Ask Tidy**, **Tasks**, **Notifications** and **Sections**. Sections is a navigation menu: meals, shopping lists, shopping websites, appointments, routines, household names, review requests, the clinic website, undated tasks and upcoming tasks each open their own focused page. Existing saved tasks and dinner plans are retained.

Meals has separate **Breakfast**, **Lunch** and **Dinner** panels. Breakfast and lunch accept typed choices for Monday to Friday, with explicit save buttons, validation, backup support and protection against conflicting edits in another tab. These optional `mealPlans` fields do not expand older backups until a plan is saved. Typed meal names do not generate ingredients or retailer orders. Dinner retains the existing meal planner, preference checks and grocery approval flow.

Ask Tidy now shows the steps it performs and opens the resulting reminder, appointment, grocery item or task. Clear local requests save automatically. Notification and alarm requests create browser reminders; an unclear time such as “6 o’clock” asks for the day and AM or PM before saving. The details form offers quick date/time choices, and the result stays highlighted on its destination screen.

Ask Tidy also gives a visible conversational reply: it acknowledges the request during processing, then confirms what it actually saved. The reply stays visible when the result opens. “Get me milk tomorrow at 7 pm” adds a shopping-list item with a Dubai-time reminder; “Get me groceries tomorrow at 7 pm” saves a reminder for the grocery trip. An existing item gains the requested reminder without creating a duplicate, while a different quantity still waits for review. Missing dates or AM/PM ask for clarification. Replies describe saved reminders and list items; they never claim a retailer order was placed. This is text feedback using the existing local rules, with no new AI or speech service.

Entered appointments are local records. Requests to book, buy or send something become drafts awaiting review; preparing or approving a draft does not contact a provider. Failed local writes remain available in the current tab and backups, and the activity panel reports the failure. Browser reminders still need Tidy open and do not create alarms in the iPhone Clock app.

The app audit fixes meal choices disappearing after preference edits, stale meal data returning after a reset, incorrect reminder interpretation, stopped routines restarting, extreme reminder timestamps breaking imported data, and stale tabs replacing newer edits. Meals keep pending preference edits for review; reminders ask when a requested time cannot be safely interpreted. Mobile pantry controls, keyboard focus and trusted meal-frame messaging are also checked.

Waitrose UAE, Kibsons, Carrefour UAE and Amazon UAE appear together in **Sections → Shopping websites**. Waitrose occupies Amazon's previous position. Amazon first offers **Open Amazon in browser** or **Try inside Tidy**, without loading Amazon or launching another page automatically. The browser choice opens a separate page with no opener; Tidy and its saved lists remain available. Other store pages make one attempt inside Tidy. If a page or security check fails, **This page is not working** stops it and shows a clear recovery message. Direct opening and retry always require an explicit click; Tidy never automatically redirects, retries or reports a purchase completed.

This handles the failed-page experience. It cannot override Amazon's security checks or establish that Amazon login/checkout works inside another website. A phone may open a direct store link in its browser or the store's app.

**Sections → Clinic website** has the **Health Square** controls. Save the clinic's actual HTTPS website address once, then use its named button. The address is browser-local, included in backups, and protected against conflicting edits in another tab. No default clinic address is supplied: the available project documents name the clinic but do not identify its website. Saving a link does not establish that the clinic permits embedded viewing or provides online booking.

Provider pages can open new windows from their own links, which some sign-in flows require. Other providers still try the embedded view first; Amazon offers its opening choices first. Tidy does not automatically open a separate window, and the embedded frame blocks direct top-level navigation. Read-only Amazon checks on 14 October 2026 saw both an embedded storefront and an Amazon security challenge; another check still returned that challenge. The cloud gateway blocked required Amazon asset/challenge hosts, so real sign-in and checkout remain unverified.

## Deployment

The `Publish Tidy website` workflow tests and builds the site on pushes to `main`, then deploys to GitHub Pages. GitHub Pages must be enabled for this repository with **GitHub Actions** as its source. The workflow's normal repository token can deploy an enabled site; enabling Pages itself requires repository-owner access or a token with the relevant administration/Pages permissions. No secret values belong in this repository.

After a successful deployment, verify the returned live URL and its `build-info.json`: it must contain the expected commit and the hashes of the published files. Then open Sections, check the focused pages and four shopping websites, and exercise the recovery controls. Do not describe a local build, a pushed commit or a saved environment draft as a published website.

The original `tidy-day-organiser.jocundridge128.chatgpt.site` hosting project is not connected to this repository. A GitHub Pages deployment would use a new address. Existing browser-saved data from the old hostname does not transfer automatically; older backup formats require a separately verified migration.

## Current limits

Tasks and meals save only on the current browser. Family names are assignment labels, not authenticated shared accounts. Google/Microsoft sign-in, cloud sync, reliable closed-app iPhone reminders, retailer baskets/orders and automatic bookings/messages are not connected. In-page reminders need Tidy open. The full native source and service configuration are still required for the iPhone version.

Before saving, Tidy refreshes browser data and checks for changes from other tabs. Editors preserve independent field changes and show conflicts rather than silently replacing the same field. Conflicting meal drafts and failed writes remain available for backup. Browser storage has no cross-tab transaction, so these protections are not a guarantee against every precisely simultaneous write; keep backups of important data.

The assistant uses explicit rules rather than a connected AI service. Unsupported time zones, reminder lead times, approximate times and ambiguous assignments require clarification. Approval buttons save preparation records; they do not perform external transactions. Real microphone, notification delivery and Safari behavior still require testing on an iPhone.
